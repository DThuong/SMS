## 1. Tóm tắt trong ngày

1. **Cài đặt trên máy MES:** đặt lại mật khẩu root MySQL, tạo database, chạy backend.
2. **Job sản lượng theo giờ (TV):** agent lấy dữ liệu màn hình *Product Time Confirm (TV)* theo ngày người dùng chọn.
3. **Đổi kiến trúc:** bỏ toàn bộ giao diện (frontend) của SMS. SMS chỉ còn **backend API + agent**. Giao diện quản trị sẽ làm bên **DYS** (https://dys.dongyang.site).
4. **Đóng gói Docker** cho API, chuẩn bị chạy ở **https://sms-backend.dongyang.site** (qua Cloudflare).
5. **Bỏ tài khoản người dùng**, chuyển sang **mật khẩu API** lưu trong database. SMS không đẩy file sang DYS nữa, DYS tự import bằng token người dùng.
6. **Agent tự xử lý sự cố MES:** tự mở MESClient, tự đăng nhập khi bị đăng xuất, tự bấm **No** khi MES hỏi nâng cấp, có **mã lỗi** rõ ràng.
7. **Làm mới database** (migration tạo lại từ đầu), sửa lỗi kiểm tra WPS trong `mes_check`.

## 2. Kiến trúc hiện tại

```
Trình duyệt DYS ──X-Api-Password──► SMS API (Docker, https://sms-backend.dongyang.site)
                                     │  MySQL `sms` + thư mục backend/storage (dùng chung)
                                     ▼
                Worker/agent (chạy thẳng trên Windows có MESClient) ── điều khiển MESClient + WPS
```
- **API** chạy được trong Docker.
- **Agent** bắt buộc chạy trên Windows có desktop, vì phải điều khiển cửa sổ MESClient và WPS. **Không chạy được trong Docker.**
- **Luồng sản lượng:** DYS gọi chạy job → SMS scan MES, lưu file `.xlsx` → DYS tải file → DYS tự gọi `POST /api/ProductionResult/import` bằng token người dùng → DYS báo kết quả lại cho SMS → SMS xóa file.

## 8. Đã kiểm tra

**Trên môi trường thử (SQLite + gunicorn):**
- Mật khẩu API: thiếu hoặc sai → 401. Header đúng → 200. Mật khẩu tạo bằng `SHA2()` qua `?password=` → 200.
- `mes_password` trả về `******`. CORS cho DYS hoạt động, origin lạ bị chặn.
- Tải file sản lượng → báo `import-result` thành công → file bị xóa, tải lại → 404.
- Job chạy trên máy không phải Windows → mã lỗi `AGENT_NOT_WINDOWS` kèm cách xử lý.
- Log truy cập không chứa `?password=`. `docker compose config` hợp lệ.

**Trên máy MES:**
- `migrate` + `seed` OK sau khi làm mới database. Tài khoản MES đã lưu (User ID `SAJLEE`).
- `mes_check` chạy lại được sau khi sửa lỗi dòng 76.

**Chưa kiểm tra:**
- Build Docker image thật: môi trường thử không tải được image từ Docker Hub.
- Tự mở MESClient, tự đăng nhập và tự bấm No trong các tình huống thật.
- Bước đặt `FROM_DATE` trên form sản lượng: chờ kết quả `probe_form`.

## 10. Việc tiếp theo
1. Chạy `python manage.py probe_form "Product Time Confirm (TV)" --export` để hoàn thiện bước chọn ngày.
2. Thử các tình huống của `mes_check`: tắt hẳn MESClient; để MES ở màn hình đăng nhập.
3. `python manage.py run_job PRODUCTION_OUTPUT` để chạy thử trọn quy trình sản lượng.
4. `docker compose up -d --build`, kiểm tra `http://<IP>:8000/api/health`, sau đó Cloudflare.
5. Làm trang quản trị agent bên DYS (Next.js).
