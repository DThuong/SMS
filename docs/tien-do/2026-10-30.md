# Tiến độ ngày 30/10/2026 (Thứ Sáu)

## 1. Tóm tắt trong ngày

1. **Giới hạn phiên API 15 phút:** API key không gọi API trực tiếp nữa, chỉ dùng để đổi lấy **token phiên** (Bearer) hạn 15 phút.
2. **Tự xóa dữ liệu sau 3 ngày:** job `CLEANUP` xóa file + dữ liệu sản lượng và kế hoạch (Work Order) cũ hơn 3 ngày.
3. **API chỉnh số ngày xóa:** `GET/PUT /api/retention`.

## 2. Phiên API

| Nội dung | Chi tiết |
|---|---|
| Tạo phiên | `POST /api/auth/session` `{"api_key": "..."}` → `token`, `expires_in` (900 giây), `expires_at` |
| Gọi API | Header `Authorization: Bearer <token>` hoặc `?token=<token>` (link tải file) |
| Hết hạn | 401 `Phiên đã hết hạn (15 phút)` → DYS tạo phiên mới |
| Cách làm | Token ký bằng `django.core.signing` (DJANGO_SECRET_KEY) + thời điểm tạo — **không cần bảng mới**, chạy được với nhiều worker gunicorn |
| Thu hồi | Khóa API key (`is_active=0`) hoặc đổi khóa → phiên cũ bị chặn ngay |
| Thời lượng | Setting `session_minutes` (mặc định 15) |

**Bỏ:** header `X-Api-Key`, query `?api_key=` (DYS phải đổi sang luồng phiên).

## 3. Tự xóa dữ liệu

- Setting mới `data_retention_days` = **3**, gộp và thay 2 setting cũ `file_retention_days` (30), `workorder_retention_days` (90) — `seed` tự xóa 2 setting cũ.
- `CLEANUP` (23:30 mỗi ngày): file cũ hơn 3 ngày → xóa file trên ổ đĩa **và** dòng `files`; `work_orders` xóa theo (CASCADE); ảnh lỗi cũ hơn 3 ngày.
- `GET /api/retention`: số ngày, mốc xóa, lịch job CLEANUP, số file sẽ bị xóa.
- `PUT /api/retention` `{"days": n}` (1–365).

## 5. Kiểm thử (SQLite)

Sai key → 401 · tạo phiên → 900 giây · không token → 401 · Bearer & `?token=` → 200 · sau 14 phút → 200 · sau 16 phút → 401 "Phiên đã hết hạn" ·
`PUT /retention` days=0 → 400, days=5 → OK · cleanup: file 4–5 ngày bị xóa (cả ổ đĩa + DB + Work Order), file 1–2 ngày giữ lại.

## 6. Việc tiếp theo

- Chạy `python manage.py seed` (Docker tự chạy khi khởi động lại) để tạo setting mới.
- DYS: đổi chỗ điền API key → gọi `POST /api/auth/session`, lưu token, gửi `Authorization: Bearer`, gặp 401 thì tạo phiên lại.
