# Tiến độ 31/10/2026

## 1. Bảng lịch sử import DYS (`import_dys_history`) — dashboard không còn trống sau khi file bị xóa

**Vấn đề:** ô "Sản lượng mới nhất" và "Kế hoạch hôm nay theo xưởng" trên DYS đọc bảng `files`, nhưng file + dòng `files` bị xóa
ngay khi import DYS thành công → job chạy thành công (#41: 40 dòng, #43: 186 dòng) mà dashboard vẫn báo "Chưa lấy".

**Thay đổi:**
- Bảng mới `import_dys_history` (model `ImportDysHistory`, migration `plans/0004_import_dys_history`): mỗi lần import DYS thành
  công ghi 1 dòng — loại, plant/xưởng (FK + mã/tên dạng chữ), ngày sản lượng / Period, tên file, số dòng, giờ xuất MES,
  giờ vào DYS (`imported_at`), người/hệ thống import, kết quả DYS trả (`dys_message`), id file cũ (`file_id`).
- Ghi trong `services.mark_import_result` (trước khi xóa file) → bắt cả 2 luồng: SMS tự import và DYS báo
  `POST /api/files/{id}/import-result`. Ghi lịch sử lỗi không làm hỏng lần import.
- `GET /api/dashboard` đọc lịch sử + file còn trên máy (chưa/lỗi import), không đếm trùng (bỏ file có trong lịch sử):
  - `today_by_oper[]` thêm `imported_at` (đã vào DYS lúc, null = chưa) và `status` (imported / import_failed / saved)
  - `production_today` giữ dạng `file_out`, thêm `source` = `history` | `file` (history: `download_url` = null)
  - `daily` (14 ngày) cũng tính từ lịch sử
- API mới `GET /api/import-history` (lọc kind, oper, report_date, date_from/date_to; phân trang như /files).
- Job CLEANUP xóa dòng lịch sử có `imported_at` cũ hơn `data_retention_days`.
- Đã thử trên SQLite: migrate, import thành công → file bị xóa nhưng lịch sử còn, dashboard hiện đúng 2 xưởng + sản lượng,
  CLEANUP xóa lịch sử cũ; `makemigrations --check` không còn thay đổi.

**Triển khai:** `docker compose up -d --build` (entrypoint tự `migrate`) hoặc `python manage.py migrate`, rồi khởi động lại worker.
Lần chạy #41/#43 sáng nay import trước khi có bảng → chưa có lịch sử; từ lần chạy kế tiếp dashboard sẽ có số liệu.
